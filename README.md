# HALOS — интернет-магазин (первый экран)

Светлый премиальный wellness-магазин в концепции «вода + природа». Фон первого экрана — утверждённые кадры `public/hero/hero-bg-desktop.jpg` (от 1024px) и `public/hero/hero-bg-mobile.jpg` (уже). Старый природный кадр сохранён в `public/hero/_archive/`. Шапка, тексты, CTA и карточка товара — живой HTML.

## Стек

Vite + React 19 + TypeScript, чистый CSS (CSS Modules + централизованные токены в `src/styles/tokens.css`), шрифты локально через `@fontsource-variable` (Playfair Display — заголовки, Inter — текст; обе с кириллицей), ESLint, Playwright (e2e).

## Команды

```bash
npm install          # зависимости
npm run dev          # dev-сервер
npm run lint         # ESLint
npm run build        # tsc -b + production-сборка (dist/)
npm run preview      # просмотр сборки (http://localhost:4173)
npm run check:contrast  # расчёт контраста пар цветов из токенов (WCAG)
npx playwright install chromium   # один раз, браузер для e2e
npm run test:e2e     # e2e на production-сборке; скриншоты — в .screenshots/ (в .gitignore)
```

`PW_CHROME_PATH=<путь к chrome>` — использовать уже установленный Chrome вместо браузера Playwright; `SHOTS_DIR` — папка для скриншотов.

## Фон и слои продукции

- Фон Hero — `<picture>`: `public/hero/hero-bg-desktop.jpg` (1280×720) от 64rem и `public/hero/hero-bg-mobile.jpg` (720×1280) ниже. Файлы байт в байт с утверждёнными оригиналами, SHA-256 проверяется e2e для `public/` и `dist/`. Без фильтров, градиентов и затемнения. Десктоп показывает кадр целиком (`aspect-ratio: 1280 / 720`).
- Генератор нарисован на самом фоне. Отдельные PNG `public/hero/generator-desktop.png` и `generator-mobile.png` лежат рядом, но на кадр не накладываются: ракурс и соотношение сторон корпуса не совпадают с фоном (десктоп около 13 %). Кликабельная зона десктопа — прозрачная кнопка по прямоугольнику корпуса.
- Прежний пульс яркости слоя прибора в стилях сохранён и на новый фон не вешается.
- **≥ 64rem**: живая шапка (логотип, меню, поиск, профиль, корзина). Заголовок, описание, CTA и преимущества — поверх левой части кадра. Прибор справа на камне — кнопка.
- **< 64rem**: тот же кадр целиком; под ним живые заголовок, описание, CTA и преимущества. Меню — в бургере. Тап по прибору открывает карточку.

## Карточка товара у прибора

- **≥ 80rem (1280px) + hover + pointer:fine (режим `overlay`)**: карточка проявляется в просвете между текстом и прибором (`CARD_RECT`) через `opacity` + `transform`, без изменения размеров блоков. Остаётся открытой, пока указатель на приборе **или** на карточке (закрытие с задержкой 500 мс — `src/config/interaction.ts`). Прибор — настоящая `<button>`: фокус с клавиатуры открывает карточку, `Tab` ведёт к кнопке, `Escape` закрывает.
- **Остальное (`flow`: телефоны, планшеты, тач и ширина < 1280px)**: карточка открывается тапом по прибору или кнопкой «Показать карточку товара» и показывается в обычном потоке под сценой.
- Данные карточки — `src/data/featuredProduct.ts`. Цена 49 990 ₽ — **демонстрационная** (помечена «Демо-цена»). Описание — ровно шесть слов.
- Кнопка «Перейти в карточку»: страницы товара ещё нет, поэтому `PRODUCT_PAGE_URL` в `src/config/routes.ts` равна `null` — кнопка помечена `aria-disabled` и при нажатии сообщает «Страница товара пока не подключена». Когда адрес появится, пропишите его в константе — кнопка превратится в обычную ссылку.

## Заглушки и открытые вопросы

- Адреса навигации, профиля, корзины, «Узнать больше» и поиска — якоря-заглушки (`src/config/routes.ts`), страниц пока нет.
- Тексты преимуществ и подпись над заголовком — нейтральные заглушки (`src/data/hero.ts`); технические характеристики и медицинские обещания намеренно не используются.
- Названия на флаконах (Omega-3, Vitamin D3, Magnesium) есть на самих изображениях упаковок; `alt` слоёв их повторяет.

## HarmonyOS Skill

Локальная копия установленного скилла лежит в `harmonyos/` (в git — только `SKILL.md` и `rules/`; справочник `harmonyos/references/` ~148 МБ добавлен в `.gitignore`). Скилл — справочник по HarmonyOS NEXT (ArkTS/ArkUI), поэтому в проекте он используется **только как источник общих принципов**: дизайн-токены вместо «магических» значений, светлая/тёмная схемы через ресурсы, анимация как плавная обратная связь без резких скачков и без анимации layout-свойств, адаптивность через контрольные точки, доступность (подписи для скринридера). Правила ArkUI/ArkTS, единицы `vp`/`dp` в веб-проект **не переносятся**: размеры заданы в `rem`, `px`, `%`, `clamp()`.
