# HALOS — интернет-магазин (первый экран)

Светлый премиальный wellness-магазин в концепции «вода + природа». На текущем этапе реализован только **Hero первого экрана**. Фон — готовое изображение-референс HALOS (`public/halos-hero-reference.png`, 1535 × 1024), подключённое **как есть**; всё интерактивное — прозрачные hotspot-зоны и живая карточка товара поверх него.

## Стек

Vite + React 19 + TypeScript, чистый CSS (CSS Modules + централизованные токены в `src/styles/tokens.css`), шрифты локально через `@fontsource-variable` (Playfair Display — заголовки, Inter — текст; обе с кириллицей), ESLint, Playwright (e2e).

## Команды

```bash
npm install          # зависимости
npm run dev          # dev-сервер
npm run lint         # ESLint
npm run build        # tsc -b + production-сборка (dist/)
npm run preview      # просмотр сборки (http://localhost:4173)
npm run check:contrast  # расчёт контраста пар цветов из токенов (WCAG)
npx playwright install chromium   # один раз, браузер для e2e
npm run test:e2e     # e2e на production-сборке; скриншоты — в .screenshots/ (в .gitignore)
```

`PW_CHROME_PATH=<путь к chrome>` — использовать уже установленный Chrome вместо браузера Playwright; `SHOTS_DIR` — папка для скриншотов.

## Фон-референс и слои поверх него

- Файл фона — `public/halos-hero-reference.png` (SHA-256 `0b9361601bc7bd29336d32cbe00e38b84ebc66e8176865044f9780638157d328`, проверяется e2e-тестом и для `public/`, и для `dist/`). Он вставлен обычным `<img>`: **без фильтров, градиентов, затемнений, размытия и масок**; масштабируется по ширине, пропорции берутся из реального файла (`aspect-ratio: 1535 / 1024`, `height: auto`). Максимальная ширина сцены — 120rem (1920px), дальше по бокам фон страницы.
- Раскладка — один файл `src/config/heroLayout.ts`: координаты зон в пикселях исходного изображения (логотип, пункты меню, поиск, иконки, CTA, прибор, флаконы, стакан, вшитая карточка). В CSS они переводятся в проценты, поэтому зоны точно следуют за фоном на любой ширине. Подстроить зону — поменять числа.
- **≥ 64rem (1024px)**: сцена на всю ширину. Над вшитой шапкой и кнопкой «Узнать больше» лежат прозрачные настоящие `<a>`/`<button>`/`<input>`, над прибором — `<button>` (hotspot). Минимальный размер зоны 44px (растёт от центра). Живые заголовок/описание/преимущества лежат в DOM и скрыты визуально (дублируют вшитые тексты для скринридеров и поиска). Реальная шапка `<Header>` на этой ширине скрыта (`display: none`).
- **< 64rem**: фон показывается целиком (без обрезки и искажений); над ним живая шапка (логотип, поиск, иконки, бургер), под ним — настоящий HTML: заголовок, описание, CTA, преимущества, кнопка «Показать карточку товара» и карточка в потоке. Тап по прибору на фоне тоже открывает карточку.
- Слои-заглушки прибора, трёх флаконов и стакана (`src/components/Scene/`, источники — `src/config/sceneAssets.ts`: `src`, `alt`, `aspectRatio`, `visible`) лежат поверх вшитых объектов **невидимыми** (`visible: false`). Чтобы заменить объект фотографией: задайте `src`, поставьте `visible: true` — но для этого нужен фон без вшитого предмета, иначе он удвоится.
- Подсветка hover/focus/active появляется только по действию пользователя (контур, подчёркивание пункта меню, кольцо на CTA и поиске); в покое все слои прозрачны — это проверяет попиксельное сравнение сцены с исходным файлом.

### Известные компромиссы вшитого фона

- **Вшитые в картинку тексты** (шапка, заголовок, описание, «Узнать больше», преимущества, карточка) растровые: не масштабируются независимо от сцены (на 1024px пункты меню ≈ 10px), не индексируются и не читаются скринридерами — поэтому рядом лежит живой HTML-текст и hotspot-зоны с `aria-label`. Картинка имеет пустой `alt`, чтобы не дублировать смысл.
- **Содержание вшитых текстов поменять нельзя**: в фоне есть формулировки «до 1200 ppb» и «Поддержка иммунитета», а живые тексты в `src/data/hero.ts` нейтральные — они расходятся. Для финала нужен новый фон либо согласование формулировок.
- **Живая карточка** (данные из `src/data/featuredProduct.ts`) по размеру чуть больше вшитой — ей нужны читаемые 16px текст и 44px кнопка. Она непрозрачная и полностью накрывает вшитую (растёт только вверх и вправо: слева и снизу — прибор и излив). Из-за разной вёрстки при проявлении на долю секунды виден кроссфейд вшитой и живой карточек.
- **Поиск**: поле лежит над вшитой строкой и в покое ничего не рисует; при фокусе или вводе получает собственную заливку (иначе набранный текст налез бы на вшитый placeholder).
- **< 64rem** вшитая шапка и заголовок остаются на фоне (картинку не обрезаем), а рядом лежит живая шапка и заголовок — на узких экранах контент визуально дублируется.
- На экранах, где сцена ниже окна (например 1280×1024), под ней виден цвет страницы.

## Карточка товара у прибора

- **≥ 80rem (1280px) + hover + pointer:fine (режим `overlay`)**: зона карточки зарезервирована внутри сцены (`CARD_RECT`) и накрывает вшитую справа сверху. Карточка лежит в ней невидимой (`opacity: 0; visibility: hidden`) и проявляется через `opacity` + `transform`, без изменения размеров блоков. Остаётся открытой, пока указатель на приборе **или** на карточке (закрытие с задержкой 500 мс — `src/config/interaction.ts`). Прибор — настоящая `<button>`: фокус с клавиатуры открывает карточку, `Tab` ведёт к кнопке, `Escape` закрывает.
- **Остальное (`flow`: телефоны, планшеты, тач и ширина < 1280px)**: карточка открывается тапом по прибору или кнопкой «Показать карточку товара» и показывается в обычном потоке под сценой.
- Данные карточки — `src/data/featuredProduct.ts`. Цена 49 990 ₽ — **демонстрационная** (помечена «Демо-цена»). Описание — ровно шесть слов.
- Кнопка «Перейти в карточку»: страницы товара ещё нет, поэтому `PRODUCT_PAGE_URL` в `src/config/routes.ts` равна `null` — кнопка помечена `aria-disabled` и при нажатии сообщает «Страница товара пока не подключена». Когда адрес появится, пропишите его в константе — кнопка превратится в обычную ссылку.

## Заглушки и открытые вопросы

- Адреса навигации, профиля, корзины, «Узнать больше» и поиска — якоря-заглушки (`src/config/routes.ts`), страниц пока нет.
- Тексты преимуществ и подпись над заголовком — нейтральные заглушки (`src/data/hero.ts`); технические характеристики и медицинские обещания намеренно не используются.
- Названия на флаконах (Omega-3, Vitamin D3, Magnesium) вшиты в фон; подписи в `alt` заглушек — условные.

## HarmonyOS Skill

Локальная копия установленного скилла лежит в `harmonyos/` (в git — только `SKILL.md` и `rules/`; справочник `harmonyos/references/` ~148 МБ добавлен в `.gitignore`). Скилл — справочник по HarmonyOS NEXT (ArkTS/ArkUI), поэтому в проекте он используется **только как источник общих принципов**: дизайн-токены вместо «магических» значений, светлая/тёмная схемы через ресурсы, анимация как плавная обратная связь без резких скачков и без анимации layout-свойств, адаптивность через контрольные точки, доступность (подписи для скринридера). Правила ArkUI/ArkTS, единицы `vp`/`dp` в веб-проект **не переносятся**: размеры заданы в `rem`, `px`, `%`, `clamp()`.
