# «Добавить» в Mini App: черновики и автопубликация

В каждом разделе админки MAX (Отзывы, Товары, Вебинары) есть кнопка «Добавить».
Записи хранятся в таблице `cms_entries` (миграция `006_cms_entries_webinar_category`),
API — `/api/admin/entries` (та же проверка initData и `MAX_REVIEW_MODERATOR_IDS`, что у остальных админ-API).

## Правило статуса
- Хотя бы одно обязательное поле пусто → **черновик**: на сайте не виден, в админке виден и редактируется.
- Все обязательные поля заполнены и прошли проверку → **опубликовано** автоматически.
- «Снять с сайта» / «Удалить черновик» → `withdrawn` (строка остаётся). Снятая запись снова появляется только по кнопке «Опубликовать снова».
- Неверное значение (не тот бренд, не YouTube, отрицательная цена) не сохраняется — форма показывает поле с ошибкой.

## Обязательные поля
| Тип | Обязательные | Необязательные |
|---|---|---|
| Товар | Название, Бренд, Категория, Цена ₽, Ссылка на фото (https или /products/…), Описание | Цена PV, Фасовка |
| Отзыв | Товар (из каталога), Имя автора, Текст | — |
| Вебинар | Название, Ссылка YouTube, Категория («о продукции» / «с врачами») | Спикер, Дата |

Источник истины — `REQUIRED_FIELDS` в `server/max/cmsEntries.ts` (клиент: `src/admin-reviews/entriesModel.ts`).

## Где появляется на сайте
- Товары: `/api/products` отдаёт `added: [...]`; сайт добавляет их в конец каталога (`custom-<id>`).
- Отзывы: добавляются к `/api/reviews` нужного товара.
- Вебинары: добавляются к `/api/webinars` с полем `category`. Вебинарам из бота категория ставится в форме вебинара (по умолчанию «о продукции»).

## Без миграции
Пока миграция 006 не применена, публичные API работают как раньше (все вебинары — «о продукции»),
а админка показывает «нужна миграция 006». Применение: `node scripts/db-migrate.mjs` с `DATABASE_URL`.
