# SILKWAY — исправление дефектов

Этот документ описывает обязательный порядок работы с багами, регрессиями, неожиданным поведением и падающими тестами. Он действует на все такие задачи в проекте, а не на один конкретный дефект.

Для задач, не связанных с дефектами, остаются доступны другие подходящие Skills проекта.

## Установленные Skills

Скиллы стоят в корне проекта, в `.agents/skills/`, и не устанавливаются в глобальный каталог пользователя. У каждого есть `SKILL.md`.

| Skill | Каталог | Источник | Назначение |
| --- | --- | --- | --- |
| systematic-debugging | `.agents/skills/systematic-debugging/` | [obra/superpowers](https://github.com/obra/superpowers) | Воспроизведение ошибки, разбор потока данных, гипотеза и исправление причины, а не симптома. |
| test-driven-development | `.agents/skills/test-driven-development/` | [obra/superpowers](https://github.com/obra/superpowers) | Сначала тест, который падает по нужной причине, затем минимальное исправление и повторный запуск. |
| verification-before-completion | `.agents/skills/verification-before-completion/` | [obra/superpowers](https://github.com/obra/superpowers) | Успех подтверждается выводом команд: тесты, сборка, diff. Без запуска команда не считается пройденной. |
| playwright-cli | `.agents/skills/playwright-cli/` | [microsoft/playwright-cli](https://github.com/microsoft/playwright-cli) | Дополнительная диагностика в браузере: DOM, консоль, сеть, трассировки, пользовательские сценарии. |

Автоматические e2e-тесты остаются на существующем `@playwright/test` (`npm run test:e2e`). Playwright CLI не заменяет этот контур.

Реестр установки CLI: `skills-lock.json`.

## Правило Cursor

Файл `.cursor/rules/bug-fixing.mdc` включён постоянно (`alwaysApply: true`).

Для задач про баг, дефект, регрессию, неожиданное поведение или падающий тест Cursor использует только четыре Skills из таблицы выше. Обычные инструменты проекта при этом разрешены: GitHub, терминал, существующие тесты, TypeScript, ESLint, Playwright test runner, DevTools и документация проекта.

## Обязательный цикл

1. Воспроизвести дефект.
2. Зафиксировать ожидаемое и фактическое поведение.
3. Прочитать исходники и недавние изменения Git.
4. Проследить данные и управление до первопричины.
5. Сформулировать опровергаемую гипотезу.
6. Написать регрессионный тест.
7. Запустить его и убедиться, что он падает по ожидаемой причине.
8. Внести наименьшее корректное исправление.
9. Повторить регрессионный тест.
10. Запустить связанные существующие тесты.
11. Проверить production-сборку.
12. Просмотреть полный diff.
13. Сообщать только то, что подтверждено выводом команд.

Если три независимых исправления не устраняют причину, правку симптомов нужно остановить и вернуться к разбору архитектуры.

Нельзя удалять падающий тест, скрывать ошибку или объявлять дефект исправленным без воспроизведения и проверки.

## Команды проверки

Скрипты из `package.json`:

```bash
npm run lint
npm run typecheck
npm run build
npm run bundle:api
npm run test:unit
npm run test:e2e
npm run check:contrast
```

`npm run test:e2e` собирает production-бандл и открывает его через Playwright. Отдельный контур e2e не добавляется.
